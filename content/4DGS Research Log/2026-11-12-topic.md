# EGGS-lite Compression Method
---
Full EGGS의 MLP factorization 제외

차용 요소
- 위치 FP16 및 G-PCC
- Luma-aware color 분리
- Volume-preserving scale 분리
- VQ/SVQ
- Huffman coding
- FP16 codebook
- LZMA 최종 패키징

### 1. Position 
: 정적 위치만 적용
```
static xyz
→ FP32 to FP16
→ uint16 변환
→ Morton 정렬
→ G-PCC 압축
```

동적 `xyz_motion`에는 G-PCC 미적용

### 2.  SH
1. SH DC 처리
```
SH DC
→ RGB 변환
→ YUV 변환
→ Y와 UV 분리
```
- Y: 높은 정밀도 또는 큰 codebook
- UV: 낮은 정밀도 또는 작은 codebook
- Y·UV 각각 VQ 적용
- VQ index Huffman coding

2. SH Rest 처리
```
SH Rest
→ coefficient 단위 또는 작은 sub-vector 단위 분할
→ SVQ
→ index Huffman coding
```

### 3. Scale
: 로그 scale 기준 분리
$$
m=\frac{s_x+s_y+s_z}{3}
$$
$$
r=s-m
$$
- `m`: Gaussian 크기 base
- `r`: 비등방성 residual
- residual 평균 0 보장
- `m` scalar VQ
- `r` SVQ
- decode 후 `s=m+r` 복원

정적 Gaussian과 동적 Gaussian의 `scaling_motion`에 동일 적용

### 4. Rotation
: 정적 Gaussian rotation만 적용
```
quaternion
→ 4차원 VQ 또는 FP16
→ decode
→ quaternion normalization
```
동적 `rotation_motion`은 원본 유지

### 5. Opacity
: 정적 opacity 및 동적 base opacity 대상
```
opacity logit
→ scalar VQ
→ Huffman-coded index
```

temporal opacity center/variance 원본 유지

# Pipeline
---
### 1. Encoding
```
Ex4DGS 학습 완료
    ↓
static / dynamic 파라미터 추출
    ↓
시간 불변 / 시간 변화 속성 분리
    ↓
정적 xyz FP16 + G-PCC
    ↓
SH DC YUV 분리 및 VQ
    ↓
SH Rest SVQ
    ↓
Scale base/residual 분리 및 VQ
    ↓
Rotation·Opacity VQ
    ↓
VQ index Huffman coding
    ↓
동적 trajectory 원본 추가
    ↓
전체 dictionary LZMA 압축
    ↓
compressed_ex4dgs.xz
```

### 2. Decoding
```
compressed_ex4dgs.xz 로드
    ↓
LZMA 해제
    ↓
정적 위치 G-PCC 복원
    ↓
Huffman index 복원
    ↓
Codebook lookup
    ↓
YUV → RGB → SH DC 복원
    ↓
Scale base + residual 복원
    ↓
Quaternion 정규화
    ↓
정적 Gaussian 복원
    ↓
동적 시간 불변 속성 복원
    ↓
원본 temporal 속성과 Gaussian index 기준 결합
    ↓
기존 Ex4DGS tensor 구조 완성
    ↓
GPU 업로드
```

### 3. Rendering
: 시점 t마다 수행
```
정적 위치 계산
xyz + xyz_disp × t / duration
    ↓
xyz_motion에서 동적 위치 보간
    ↓
rotation_motion에서 Slerp
    ↓
temporal opacity 계산
    ↓
복원된 동적 SH·scale·opacity 결합
    ↓
정적 Gaussian + 동적 Gaussian concatenate
    ↓
기존 Ex4DGS rasterizer 실행
```

# Cost
---
### 1. Loading

추가 비용
- LZMA 해제
- G-PCC decode
- Huffman decode
- codebook lookup
- GPU 업로드

### 2. Frame Rendering

추가 압축 연산 없음
- 디코딩된 속성 캐싱
- 기존 Ex4DGS 보간 사용
- 기존 rasterizer 사용
- FPS 변화 거의 없음 예상

### 3. Memory

- 디스크 크기 감소
- 전송량 감소
- 디코딩 후 GPU 메모리 원본과 유사
- runtime memory compression 미포함
